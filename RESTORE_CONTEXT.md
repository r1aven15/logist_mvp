## Зачем приложение

- Учёт транспорта, рейсов, топлива, ремонтов, склада, водителей и налогов.
- Помогает небольшим автопаркам видеть прибыль по рейсам и не терять деньги.
- Демо — для показа клиентам. Рабочая версия — для реальной конторы.
- Требования: ссылки стабильные; демо отдельно; в демо не должно быть реальных данных; рабочая база не должна затрагиваться.

## Топливо в процентах

- В карточке машины есть режим датчика топлива: **литры** или **проценты**.
- 750-я машина (`glonass_505725`): бак **70 л**, норма **15,6 л/100 км**, режим **литры**, резерв **0**. Приложение показывает данные ГЛОНАСС **без поправки**. Последний синк 27.11.2026: сырые **34,05 л** / **48,76%**; если датчик врёт, это калибровка на стороне ГЛОНАСС, а не приложения.
- В режиме процентов приложение показывает **%** как основное значение, а литры — для запаса хода и суммы по парку.
- При полном баке 70 л и норме 15,6 приложение показывает около **449 км** запаса.
- ГЛОНАСС отдаёт сырые **литры** (`34.05`), скрипт пишет и `fuelPercent=48.76`; приложение показывает это значение без поправки. Главное — чтобы синк обновлялся; последние данные приходят каждые 5 минут.
- Проверено Playwright: ручной режим, 39.57% → 40% и ~27,7 л, 100% → ~449 км, сохранение режима и бака.
- Есть галочка **«Ручной ввод топлива»**: она игнорирует ГЛОНАСС по топливу для выбранной машины и показывает введённое значение; удобно, когда датчик врёт или синка нет.
- Поправка датчика **не используется** — Владимир попросил убрать её и показывать данные ГЛОНАСС как есть.
- «Заправка» в журнале принимает литры, а в режиме процентов пересчитывает их в проценты по объёму бака.
- Для 750-й новые поля восстанавливаются сами: если старый клиент сохранил карточку без `fuelSensorMode`, приложение ставит 70 л, 15,6 и **литры**. Режим «Литры» сохраняется; принудительного процента больше нет.

## Как восстановить

### Если есть архив `ap-2026-11-23-...zip`

1. Распаковать архив. Внутри будет папка `autopark-restore-2026-11-23`.
2. Перейти в неё: `cd autopark-restore-2026-11-23`.
3. `pip install -r server/requirements.txt`
4. `python3 restore.py --target /workspace/project --force`
5. Проверить `firebaseConfig` и `const DOC_REF = doc(db, "gazelle_app", "main_data");`.
6. Проверить синтаксис модульного скрипта: `node --check`; открыть `app.html`.
7. Если Firestore недоступен — использовать `data/firestore-main_data.json` и `data/firestore-backups.json`.
8. Не публиковать `secrets/` и `.secrets/`.

### Если проект уже развёрнут в `/workspace/project`

1. `pip install -r requirements.txt`
2. Проверить, что на месте `index.html`, `app.html`, `demo*.html`, `crm/`, `outreach/`, `data/`, `secrets/`.
3. Проверить `firebaseConfig` и строку `DOC_REF`.
4. Проверить синтаксис модульного скрипта и открыть `app.html`.
5. Если Firestore недоступен — взять данные из `data/`.
6. Не публиковать `secrets/` и `.secrets/`.
