# Красноярск: письма и рассылка

Это набор для аккуратного первого контакта с компаниями Красноярска.
Он не рассылает спам: по умолчанию готовит письма в папку `outbox/`,
а отправляет только адресатам, у которых в CSV стоит согласие.

## Важно по закону

- Реклама по e-mail без предварительного согласия адресата ограничена
  ст. 18 Федерального закона «О рекламе» (38-ФЗ). За нарушение бывают штрафы.
- Не покупайте базы адресов и не отправляйте письма на личные адреса без согласия.
- Берите только публичные корпоративные адреса с сайтов компаний, 2ГИС,
  Яндекс.Карт или из открытых карточек организаций.
- В каждом письме есть фраза «ответьте "нет", больше не напишу» — это простой opt-out.
- Лучше 10–20 персональных писем в день, чем 500 одинаковых.

Если нужен холодный первый контакт без согласия — используйте не массовую
рассылку, а персональные письма/звонки. Шаблоны ниже для этого и сделаны.

## Что внутри

- `01-first-letter.txt` — первое письмо.
- `02-follow-up.txt` — одно напоминание через 3–5 дней.
- `03-accountant-partner.txt` — письмо бухгалтерам, интеграторам 1С и партнёрам.
- `04-subjects.txt` — варианты тем.
- `05-call-script.txt` — что спросить по телефону.
- `06-messenger.txt` — короткое сообщение в мессенджер.
- `07-email-after-call.txt` — письмо после разговора.
- `08-max-message.txt` — короткие сообщения для MAX: клиенту, партнёру, follow-up.

- `.env.example` — настройки почты.

## Настройка почты

Создайте отдельный ящик для рассылки, например на Яндексе или Mail.ru.
Включите двухфакторную защиту и создайте «пароль приложения» для SMTP.
Обычный пароль от почты не используйте. Подробная инструкция — в `SETUP-MAIL.md`.

Скопируйте `.env.example` в `.env` и заполните:

```bash
cp outreach/.env.example outreach/.env
```

Для Mail.ru:

```text
SMTP_HOST=smtp.mail.ru
SMTP_PORT=465
SMTP_MODE=ssl
SMTP_USER=ваш-ящик@mail.ru
SMTP_PASSWORD=пароль-приложения
SMTP_FROM=ваш-ящик@mail.ru
SMTP_NAME=Ваше имя
```

Для Яндекса: `smtp.yandex.ru`, порт `465`, режим `ssl`.
Для Gmail: `smtp.gmail.com`, порт `587`, режим `starttls`, нужен пароль приложения.

`.env` не коммитьте в git и не отправляйте никому.

## Как подготовить письма

1. Заполните `recipients.csv` по образцу `recipients-template.csv`.
2. Для адресатов, которые уже дали согласие, поставьте `consent=yes`.
3. Проверьте текст и подставьте свои данные.
4. Сгенерируйте черновики:

```bash
python outreach/send_offer.py \
  --recipients outreach/recipients.csv \
  --template outreach/01-first-letter.txt
```

Черновики появятся в `outreach/outbox/`. Письма без вложений: только ссылка
на презентацию с демо и ценами. PDF и `demo-krsk-standalone.html` остаются
в комплекте на случай, если адресат попросит файл.

## Как отправить согласным

Только для адресатов с `consent=yes`:

```bash
python outreach/send_offer.py \
  --recipients outreach/recipients.csv \
  --template outreach/01-first-letter.txt \
  --send --confirm-consent --limit 20 --delay 30
```

Скрипт остановится, если нет `--confirm-consent` или у адресата нет согласия.
Максимум по умолчанию — 20 писем за запуск.

Категории для поиска в 2ГИС и Яндекс.Картах:

- грузоперевозки и логистика;

персональным, а не холодным спамом.

## Что говорить про 1С и телематику

- Сейчас в приложении есть выгрузка **Excel (CSV)**, **1С (CSV)** и **Машины CSV**.
- 1С загружает CSV через обработку; колонки под конкретную конфигурацию настраиваются.
- Прямая автоматическая синхронизация с 1С через API/ODBC — отдельный проект, не в базовой версии.
- Базовая телематика — ГЛОНАСС. Wialon, Omnicomm, Автограф, SCOUT и другие подключаются через адаптер по API.
- Не обещайте «полную интеграцию за день»: сначала демо, потом состав данных и сроки.

## Что говорить про сервер и размещение

- Демо сейчас на временном бесплатном сервере. Для постоянной работы нужен свой домен и сервер.
- «Облако»: хостинг, обновления и резервные копии уже входят в подписку.
- «Сервер клиента»: сервер/VPS, домен и администрирование оплачивает клиент; настройка и перенос — отдельная смета.
- Ориентир для 5–30 машин: VPS 700–1 500 ₽/мес, домен 200–400 ₽/год, SSL бесплатно.
- Если нужны персональные данные водителей — рекомендуйте российский сервер и настройку под 152-ФЗ.
- Не обещайте «всё на вашем сервере» без замены Firebase: текущая версия хранит данные в Google Firestore. Для полностью локального хранения нужен отдельный backend (Supabase/PocketBase/PostgreSQL) или 1С.
